# Mobile and accessibility verification

Step 10 completed on 23 October 2026. The production build passes 131 targeted checks and 22 axe-core 4.14 audits with zero automated violations in the tested states. Existing keyboard, touch, navigation and contact-form regression tests pass all 115 checks. Lint, TypeScript and production build pass.

Tested viewports: 320×740, 360×800, 390×844, 430×932, 768×1024, 920×900, 1024×768, 1440×1000 and 844×390 landscape. Text enlarged to 200% was verified at 320, 768 and 1440px, including expanded value cards. Checked states include both comparison modes, Marketplace/audience tabs, valid and expired SOAT samples, flipped values and invalid contact fields. The report retains axe findings requiring manual review rather than treating them as automatic passes.

Changes include wrapping calls to action, readable contrast within the brand palette, 44px control heights, non-overlapping mobile prosperity controls, scrolling landscape navigation, a non-sticky mobile journey graphic, all three gallery images, cards that grow with their text, skip navigation, corrected heading/ARIA semantics, stable accessible headline/counter text, value descriptions in the accessibility tree, visible keyboard focus, and a page motion-pause control alongside system reduced-motion support.

Compared with the baseline screenshots, intentional differences are darker orange text on light backgrounds, dark text on orange buttons/cards, stacked comparison cards on mobile, prosperity controls below the mobile graphic, and the full mobile gallery. Parkinsans remains primary; the supplied DK Cool Crayon font and previously requested larger hero image remain in place. Section order, source assets and original reference files are preserved. Screenshots in `screenshots/` cover hero, comparison, prosperity, offerings, journey, SOAT, finder, gallery, contact and enlarged text. `before.json` records the initial issues; `audit.json` records final results.

Run a production build and start it on a free local port, then run `npm run test:accessibility` with `TEST_ORIGIN` set to that origin. The default is http://127.0.0.1:3000. Verification tooling uses Node.js 24 and headless Chrome; override `CHROME_PATH` if necessary. The accessibility audit submits only an empty form to check client-side validation. It does not save enquiries. Use `npm run test:interactions` for the broader interaction/form suite.

Checks cover WCAG A/AA tags and axe best practices, plus keyboard, touch-target geometry, focus visibility, accessibility-tree names and descriptions, reflow and reduced motion. Browser emulation and automated checks do not constitute formal WCAG certification or physical VoiceOver/TalkBack testing. Relevant criteria are described in the [W3C WCAG 2.2 standard](https://www.w3.org/TR/WCAG22/).
